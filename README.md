# A 股量化分析与选股研究系统

一套在 Windows 本地运行的 A 股量化研究工具：Web 界面基于 Streamlit，行情取自东方财富、新浪财经等公开接口，建模使用 LightGBM / XGBoost，统计检验使用 Statsmodels。

系统的原则是**不伪造结果**：拿不到行情就显示错误或标注为缓存，模型没通过样本外验证就不输出评分，没有统计依据就不生成套利信号。所有页面都会显示数据来源、行情时间和采集时间。

> 各模块的详细口径、限制与实现说明见 [docs/详细说明.md](docs/详细说明.md)。

## 功能

### 页面一 · 个股分析

- 按代码或名称搜索 A 股，展示最新价、涨跌幅、成交量额、当日开高低收。
- 日 K / 周 K 及成交量图表，常用技术指标与传统多因子指标。
- LightGBM 与 XGBoost 的预测、特征重要性、时间序列样本外验证结果。
- 参考买入区间、初始止损、止盈与趋势退出条件（由 ATR 等明确规则计算，不换算绝对价格）。
- 单标的回测，以及配对股票的统计套利研究。

### 页面二 · 量化选股

- 扫描沪深主板、创业板、科创板或自定义股票池，默认排除 ST、退市整理与数据不完整股票。
- 结果展示多因子评分、两个模型的排名、预测周期、参考入场/止损/退出条件与主要风险，可跳转到页面一。
- 扫描前可选训练目标（排序 / 回归 / 自动择优）、滚动训练窗口长度、是否启用市值与行业中性化。
- 可勾选在同一轮扫描后运行 **Top-N 组合回测**，直接查看组合与基准净值、换手率、费用拖累、未成交笔数，以及每笔成交和每段训练窗口的明细。
- **扫描只由管理员触发**：一轮扫描训练出的截面模型是所有账号共用的，谁扫谁就决定别人明天看到什么。普通账号打开本页没有「开始扫描」按钮，看到的是最近一次扫描的只读排名，顶部标明这一版是谁在什么时候跑的。平日由收盘后的定时任务统一刷新，见下节。
- 页面上的行情接口成功率、逐股失败原因与代理诊断只对管理员展开——那是运维信息。

### 收盘后的每日全市场扫描

管理员不必每天手动点一次。`scan_daily.py` 是独立于网页的进程，按与管理员手动全市场扫描**完全相同的口径**（沪深京全部 A 股 + 中性化 + 扩展因子，关掉逐股回测与组合回测）跑一轮，并把结果落盘供所有人查看：

```powershell
.venv\Scripts\python.exe -X utf8 scan_daily.py --dry-run   # 只看本次参数与跳过原因，不联网、不落盘
.venv\Scripts\python.exe -X utf8 scan_daily.py             # 正常执行，已跑过就跳过
.venv\Scripts\python.exe -X utf8 scan_daily.py --force     # 忽略跳过判定，立即扫描
```

两道前置判定按顺序生效，命中任意一条就**不训练、不落盘**并以退出码 0 结束：

1. **数据就绪**：沪深 300 已完成日线的最后一根必须是今天。收盘后行情源的当日 K 线有时晚几分钟才出，此时若照常扫描，逐股采集会把整池判成「历史行情未更新」而大批排除，训练出一个几乎是空截面的模型并**静默覆盖掉原本可用的好模型**——这是本功能最危险的失败模式。
2. **幂等**：已落盘模型上下文的截面日期已经是今天就不再重复训练。周末与节假日靠这条自然覆盖，不需要维护交易日历。

网页端与定时进程写的是同一份模型与面板文件，两边共用数据库咨询锁 `settings.COMPUTE_LOCK_KEY`，因此不会同时训练并互相覆盖；锁被占用时定时任务记日志并以退出码 1 结束，不做排队。

Windows 计划任务（**请自行确认后再执行**）：

```powershell
schtasks /create /tn "量化每日扫描" /tr "D:\github\quant\run_daily_scan.bat" /sc weekly /d MON,TUE,WED,THU,FRI /st 15:30
```

Linux 用 `deploy/quant-scan.service` + `deploy/quant-scan.timer`，见 [deploy/README.md](deploy/README.md)。**服务器时区必须是 `Asia/Shanghai`**，`OnCalendar` 用的是系统时区。

### 页面三 · 自选与持仓

- 自选增删与监控开关；分批录入买入日期、价位、股数、可卖股数与费用。
- 汇总成本与带源时间的参考浮盈亏；持仓编辑使用行锁与版本号防止覆盖，删除保留审计记录。

### 页面四 · 盘中监控

- 3~60 秒快照轮询、30~300 秒分钟线同步，独立后台任务，关掉浏览器页面不会停止。
- 单股规则使用卡尔曼滤波估计参考价，遵守 T+1 与手工确认的可卖数量。
- 配对监控只用当日之前的历史检验协整与对冲比例稳定性，未确认借券条件时只显示观察。

### 页面五 · 账号管理（仅管理员可见）

- 管理员创建账号时**只填用户名**：新账号处于「待激活」状态、暂时无法登录，密码由使用者本人在登录页选择「首次激活」自行设置，管理员全程不经手、也无从得知。
- 重置密码同理——退回「待激活」并立即撤销该账号全部会话，新密码仍由本人重新设置；禁用后无法登录，可随时恢复。
- 账号清单展示状态（正常 / 待激活 / 已禁用）、角色、创建时间与最近登录；不提供删除，只提供禁用。
- 该页面只对管理员注册为路由，普通账号在导航里看不到，也无法通过页面地址直接打开。
- 系统禁止禁用或重置「最后一个可登录的管理员」，也不会让管理员禁用自己正在使用的账号，避免把所有人锁在门外。

## 建模与工程要点

**排序目标替代回归目标。** 直接用 MSE/MAE 回归未来收益时，树模型在全市场普涨下会退化成"全线看多"。因此默认把每个交易日的截面收益按分位映射为 5 级相关度，用 LambdaMART（LightGBM）或 `rank:ndcg`（XGBoost）直接优化截面内排序，`group`/`qid` 为交易日——"看多"只在同日截面内部成立。排序输出是无量纲的相对分数，页面按同日截面百分位展示，不会当成预期超额收益；只有回归目标才给出有量纲的预期收益。也可选「自动择优」同时训练两种目标，按样本外 Rank IC 择优，并把两边的指标写进结果供复核。

**滚动窗口重训（Walk-Forward）。** 废弃静态全量训练，每次重训默认只取最近 750 个交易日（约 3 年）的样本，让策略跟上 A 股风格切换。窗口按完整交易日截取，窗口内训练标签的结束日仍必须严格早于测试起日，不会因截断而泄漏未来；设为 0 表示使用全部历史。

**市值与申万一级行业中性化。** 对每个交易日的股票截面，以流通市值对数与行业哑变量做多元线性回归，取残差作为纯净 Alpha 因子，避免模型只学到"买大市值白马"或"追热门板块"。同一天的全部因子使用相同有效样本，覆盖率低于 50% 时自动退回截面 Z 分数因子，并把跳过原因（截面不足 / 因子整体缺失）写入上下文。另补充短期反转（1 日 / 3 日收益）、Amihud 非流动性、量价背离等特征。

**Parquet + DuckDB 列式存储。** 大规模面板不再走 SQLite 行式存储：清洗后的日线、因子面板、市值行业暴露、PIT 财务面板与累积的分钟线统一落盘为 Parquet（zstd 压缩，按 `adjustment=*/code=*.parquet` 分区，先写临时文件再原子替换）。DuckDB 把 Parquet 目录映射成视图做只读即席查询。未安装 duckdb 时退回口径一致的 pandas 向量化实现，并有等价性单测。

**股票池先过生存者偏差关。** 退市、退市整理期与 ST / \*ST 标的在扫描、因子计算与回测之前一律排除，用户自定义代码也不例外。状态取自交易所退市名单与全市场 ST 名单（缓存一天），名单不可用时退回证券简称启发式，并在页面上如实标注当前用的是哪一套。名单覆盖不到的代码不会被默认放行。

**PIT 点时财报多因子。** 财务数据不按报告期结束日、只按交易所实际公告日对齐：DuckDB `ASOF JOIN` 严格取"公告日 < 交易日"的最近一期，公告日当天不生效。每个报告期的「生效日」取计算中实际回看窗口（4 个单季 + 1 个上期累计）内**最晚**的公告日——上一年年报与本年一季报都落在四月，一季报常常**早于**年报披露，只按本期公告日对齐会让 TTM 指标提前引用尚未公开的年报数据。因子覆盖盈利质量（TTM 扣非 ROE、经营现金流净额／净利润）、成长动能（单季营收同比、单季扣非净利同比及其环比变化）与财务健康（Altman Z''，X1 营运资金 / X2 留存收益 / X3 息税前利润 / X4 账面权益）。Z'' 用于非制造业与新兴市场、X4 以账面权益计量，与"不掺入价格"的口径自洽，因此阈值取 1.10 / 2.60 而非原始 Z（1968）的 1.81 / 2.99。报表数据按行业模板取：数据源把定期报告分成通用／银行／保险／证券四套互不重叠的模板，利润表的通用模板覆盖全部行业，但资产负债表与现金流量表的通用模板不含金融板块，故这两张表逐一套模板抓取后合并——只取通用模板会让银行、保险、证券共约 193 只股票静默丢掉这两张表，而覆盖率门控看不出板块级缺失。金融股因此只算能算的部分；银行资产负债表本就没有流动／非流动划分，Z'' 的 X1 与 X3 无从取值，Z 保持为空，这是正确结果而非缺陷。判定为困境区或经营现金流恶化的标的被**一票否决**：在截面标准化之前就整行移出面板，因此这类股票既不会被选中，也不会参与自己所在截面的均值与标准差——拿不到 PIT 财务数据的行是"未知"而非"健康"，不会因为缺失被误杀。

**筹码分布集中度。** 按价格分箱滚动模拟筹码堆积：每个交易日新增成交量按三角分布摊在当日高低价之间，历史筹码按换手率指数衰减。输出 90% 成本区间宽度与获利盘比例——区间越窄说明筹码越集中、套牢盘越少。历史不足 120 个交易日时不出因子，不用短样本冒充稳态筹码。

**日内波动率衰减与订单流不平衡代理。** 把连续竞价切成 8 个 30 分钟区间，逐区间算分钟收益率标准差，对区间序号回归得衰减斜率，并给出「尾盘 30 分钟 / 开盘 30 分钟」波动比。订单流方面，本地没有 L2 逐档快照，用分钟线做两个代理：按涨跌方向拆分的主动买卖量净额，以及成交均价在当日高低区间中的位置（改用「分钟典型价按成交量加权」以避免成交量单位不一致造成的量级漂移）；标准 OFI（Cont 等 2014）已按最优买卖价与挂单量变动的口径实现，接入 L2 后可直接替换。某交易日的日内因子只由该交易日的分钟线计算，不跨日、不插补。

**新增因子按覆盖率门控自动并入。** 三类新因子走同一个下沉层并入排序特征矩阵：整族因子齐全的行占比达到 50% 才纳入训练，否则整族不参与，而不是把大量缺失值塞进特征矩阵让模型去猜；纳入后与基础因子一起做截面 Z 分数标准化，并沿用既有的 Rank IC、HAC t 检验等样本外验收关卡。日内因子受免费分钟线深度限制，本地按日累积落盘以逐步加长历史深度。

**加载阶段异常清洗。** 前复权序列出现超过板块涨跌幅上限 1.2 倍的跳空时按复权口径剔除（上市初期不参与判定）；连续停牌达 20 个交易日标记为长期停牌，不进入当日截面；全天无振幅且触及涨跌停的一字板标记为流动性锁定，不假设成交。清洗只标注与剔除不可信 K 线，不改写原始价格。

## 交易摩擦与风控口径

组合回测按每日截面把模型排序融合后取前 N 名（默认 20）等权持有，单股仓位上限默认 5%，超出部分留现金、不放大杠杆。撮合严格模拟 A 股制度：

- **T+1**：当日开盘买入最早次日开盘卖出。
- **涨跌停**：开盘一字涨停不假设买入成交，开盘一字跌停不假设卖出成交。
- **停牌**：不交易，按最近收盘价估值。
- **成本**：卖出收 0.05% 印花税，买卖双边各收 0.03% 佣金与 0.1% 滑点，逐笔记录未成交笔数。

打分股票池与撮合股票池强制一致：流动性筛选裁剪股票池后，截面面板同步裁剪，避免排序选中根本没有行情、无法成交的股票。

**模型验证不通过就不输出评分。** 排序目标要求每日 Rank IC > 0.02 且 HAC t > 1.645、NDCG@截面前 20% 高于随机基线 5% 以上、Top 超额为正并优于池均值、Top-Bottom 为正、至少 40 个样本外交易日；回归目标仍按 MAE 中位数基线判定。滚动重训的每一段都会把实际检验数值（`rank_ic`、`ndcg_ratio`、`mae`、`training_dates`、当时生效的验证规则）写进记录，被门槛拦下时能直接看出是哪一条没过、差多少。

## 技术栈

| 用途 | 选型 |
| --- | --- |
| 界面 | Streamlit |
| 数据处理 | Pandas、NumPy |
| 建模 | LightGBM、XGBoost（LambdaMART / `rank:ndcg`） |
| 统计检验 | Statsmodels（协整、HAC） |
| 面板存储 | Parquet + DuckDB |
| 本地缓存 | SQLite |
| 业务数据 | PostgreSQL（自选、持仓、监控、回测存档） |

行情获取、因子计算、模型预测、策略信号与页面展示是分离的模块。

## 快速开始

需要 64 位 Python 3.11 或更新版本。Windows 下双击 `run.bat` 会自动创建虚拟环境、安装依赖并启动。

手动执行：

```powershell
py -3 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe -m streamlit run app.py
```

Linux / Nginx 部署见 [deploy/README.md](deploy/README.md)。

首次启动会要求登录，应用会自动补齐初始管理员：**用户名 `admin`，密码 `admin123`**。登录后在侧边栏「修改密码」自行更换。

> `admin123` 是公开写在本文件里的默认口令，知道它的人都能登录并管理账号。请**先改密码再对外提供服务**：未更换前，账号管理页会持续显示告警。密码支持 8 至 128 位，常见弱口令会被拒绝。

后续账号由管理员在「账号管理」页创建，不提供网页注册。也可以继续用命令行：

```powershell
.venv\Scripts\python.exe manage_users.py create alice --temporary
```

`--temporary` 创建的临时密码首次登录后仍会强制修改（至少 8 位）；网页端创建的账号则走「首次激活」，两者互不影响。

## 配置数据库

业务数据（自选、持仓、盘中监控、回测存档、账号）保存在 PostgreSQL 的 `public` 模式，首次启动会自动执行 `sql/` 下的建表脚本，不会覆盖已有数据。

1. 复制模板并填入自己的连接信息：

   ```powershell
   copy config\database.example.json config\database.local.json
   ```

   ```json
   {
     "host": "127.0.0.1",
     "port": 5432,
     "dbname": "quantify",
     "user": "postgres",
     "password": "请填写数据库密码"
   }
   ```

2. `config/database.local.json` 已被 `.gitignore` 忽略，**不会进入版本库**，可以放心写本机口令。仓库里只保留 `config/database.example.json` 这个占位模板。

   - 不复制也能启动：连接项会退回到 `127.0.0.1` / `5432` / `quantify` / `postgres` / 空口令，只适合本机无口令的开发库。
   - 由于该文件不进版本库，每位协作者都需要各自复制一次。
   - `git update-index --skip-worktree` 之类的旧办法不再需要。

3. 也可以改用环境变量覆盖其中任意一项，环境变量优先级更高：

   | 变量 | 含义 |
   | --- | --- |
   | `QUANT_PG_HOST` | 主机 |
   | `QUANT_PG_PORT` | 端口 |
   | `QUANT_PG_DBNAME` | 数据库名 |
   | `QUANT_PG_USER` | 账号 |
   | `QUANT_PG_PASSWORD` | 密码 |

密码只从配置文件或环境变量读取，不写死在源码里，也不会进日志。`config/database.local.json` 不进版本库，仓库里只有上面那份占位模板；数据库不可用时会明确报错，不会退回临时内存假装保存成功。

## 已知限制与免责声明

- **不构成投资建议。** 扫描与策略信号是研究结果，历史回测不代表未来收益。
- 行情接口免费且无 SLA，可能限流、延迟或变更；实时行情、最近收盘行情与缓存行情会被明确区分，过期数据不会用于生成扫描预测。
- 估值（PE/PB）与相对行业基准的强弱仍未接入；相对强弱目前只对比沪深 300。
- 股票池过滤用的是**当前**退市与 ST 名单，能在扫描与回测前挡掉当下的问题股，但**无法还原历史时点的成分股**：过去某天它是正常股还是 ST，本地没有历史状态序列，因此回测净值为"本次实际采集股票池"内按模型排序的结果，幸存者偏差只被削弱、未被消除。
- PIT 财务因子的公告日取自巨潮资讯披露日历，财报数值取自东方财富 F10 报表接口。两者口径不一致或接口改版时可能对不齐，此时该期留空而不是回退到报告期，避免静默引入未来函数；因此实际覆盖率受接口可得性影响。
- 金融股（银行／保险／证券）的财务因子中，只有 Altman Z'' 为空：它们的资产负债表没有流动／非流动划分，Z'' 的 X1 与 X3 无从取值。其余因子（TTM 扣非 ROE、经营现金流／净利润、单季营收同比、扣非净利同比及加速）都有数，因为利润表取的是覆盖全部行业的通用模板。Altman Z'' 本就不适用于金融企业，让它留空好过算一个不能解释的数。
- 财务面板按股票分区缓存，已落盘的分区不会因取数口径变更自动重拉。若在「资产负债表与现金流量表补齐金融板块」这一改动之前建过面板，需要显式刷新（`build_fundamental_panel(..., refresh=True)`）才会补上金融股的这两张表。
- 历史市值由"当前流通市值 ÷ 当前价 × 历史收盘价"近似，行业使用当前申万一级分类，均非严格点时数据。
- 筹码分布只用日线的最高／最低／收盘与换手率做三角分布近似，不是真实的逐笔成本分布；免费分钟线单次仅返回最近约 5 个交易日（1 分钟），日内因子的历史深度靠本地逐日累积。
- 日内订单流为**代理指标**，由分钟线按涨跌方向拆分成交量近似，不等同于 L2 逐笔委托流；标准 OFI 虽已实现，但在未接入 L2 盘口前不会被调用。
- 费率按比例近似，未模拟最低佣金、整手与盘口深度；未完整模拟 IPO 特殊涨跌幅与精确分红税。
- 分钟级信号不等同于交易所级高频交易，未接入逐笔行情、委托、撤单或券商回报，不会自动下单。
