# A 股量化分析与选股研究系统

一套在 Windows 本地运行的 A 股量化研究工具：Web 界面基于 Streamlit，行情取自东方财富、新浪财经等公开接口，建模使用 LightGBM / XGBoost，统计检验使用 Statsmodels。

系统的原则是**不伪造结果**：拿不到行情就显示错误或标注为缓存，模型没通过样本外验证就不输出评分，没有统计依据就不生成套利信号。所有页面都会显示数据来源、行情时间和采集时间。

> 各模块的详细口径、限制与实现说明见 [docs/详细说明.md](docs/详细说明.md)。

## 功能

### 页面一 · 个股分析

- 按代码或名称搜索 A 股，展示最新价、涨跌幅、成交量额、当日开高低收。
- 日 K / 周 K 及成交量图表，常用技术指标与传统多因子指标。
- LightGBM 与 XGBoost 的预测、特征重要性、时间序列样本外验证结果。
- 参考买入区间、初始止损、止盈与趋势退出条件（由 ATR 等明确规则计算，不换算绝对价格）。
- 单标的回测，以及配对股票的统计套利研究。

### 页面二 · 量化选股

- 扫描范围固定为**沪深京全部 A 股**，默认排除 ST、退市整理与数据不完整股票。排名与评分是所有账号共用的，只扫某个板块会让其他人看不到其余板块的结论。
- 结果展示多因子评分、两个模型的排名、预测周期、参考入场/止损/退出条件与主要风险，可跳转到页面一。
- 扫描前可选训练目标（排序 / 回归 / 自动择优）、滚动训练窗口长度、是否启用市值与行业中性化。
- 需要临时验证某几只代码时，可在「更多（可选）」里填自定义代码试跑：结果只留在本页，不落盘、不覆盖其他人看到的全市场结论。
- **扫描只由管理员触发**：一轮扫描训练出的截面模型是所有账号共用的，谁扫谁就决定别人明天看到什么。普通账号打开本页没有「开始扫描」按钮，看到的是最近一次扫描的只读排名，顶部标明这一版是谁在什么时候跑的。平日由收盘后的定时任务统一刷新，见下节。
- 页面上的行情接口成功率、逐股失败原因与代理诊断只对管理员展开——那是运维信息。

### 收盘后的每日全市场扫描

管理员不必每天手动点一次。`scan_daily.py` 是独立于网页的进程，按与管理员手动全市场扫描**完全相同的口径**（沪深京全部 A 股 + 中性化 + 扩展因子，关掉逐股回测与组合回测）跑一轮，并把结果落盘供所有人查看：

```powershell
.venv\Scripts\python.exe -X utf8 scan_daily.py --dry-run   # 只看本次参数与跳过原因，不联网、不落盘
.venv\Scripts\python.exe -X utf8 scan_daily.py             # 正常执行，已跑过就跳过
.venv\Scripts\python.exe -X utf8 scan_daily.py --force     # 忽略跳过判定，立即扫描
```

两道前置判定按顺序生效，命中任意一条就**不训练、不落盘**并以退出码 0 结束：

1. **数据就绪**：沪深 300 已完成日线的最后一根必须是今天。收盘后行情源的当日 K 线有时晚几分钟才出，此时若照常扫描，逐股采集会把整池判成「历史行情未更新」而大批排除，训练出一个几乎是空截面的模型并**静默覆盖掉原本可用的好模型**——这是本功能最危险的失败模式。
2. **幂等**：已落盘模型上下文的截面日期已经是今天就不再重复训练。周末与节假日靠这条自然覆盖，不需要维护交易日历。

网页端与定时进程写的是同一份模型与面板文件，两边共用数据库咨询锁 `settings.COMPUTE_LOCK_KEY`，因此不会同时训练并互相覆盖；锁被占用时定时任务记日志并以退出码 1 结束，不做排队。

Windows 计划任务（**请自行确认后再执行**）：

```powershell
schtasks /create /tn "量化每日扫描" /tr "D:\github\quant\run_daily_scan.bat" /sc weekly /d MON,TUE,WED,THU,FRI /st 15:30
```

Linux 用 `deploy/quant-scan.service` + `deploy/quant-scan.timer`，见 [deploy/README.md](deploy/README.md)。**服务器时区必须是 `Asia/Shanghai`**，`OnCalendar` 用的是系统时区。

### 页面三 · 自选与持仓

- 自选增删与监控开关；录入一笔持仓的必填项只有代码、买入日期、买入价、持仓股数，名称、可卖股数、费用、备注收进「更多（可选）」。
- 股数以整手加减，步长 100 股；编辑表首列是「删除」，勾选即删，删除保留审计记录。
- 汇总成本与带源时间的参考浮盈亏；持仓编辑使用行锁与版本号防止覆盖。
- 每日人工调仓任务单对照完整全市场模型 Top N，区分调出、调入、维持与待核查；保留含费用成本、T+1 可卖数、固定成本止损和趋势退出原因。缺失或过期排名不等于跌出 Top N，流动性、行情或风控缺失不生成买入任务。

### 页面四 · 盘中监控

- 3~60 秒快照轮询、30~300 秒分钟线同步，独立后台任务，关掉浏览器页面不会停止。
- **监控范围只有开启监控的自选和全部持仓**，其余代码一律不订阅，最多 50 只；配对等研究用代码不占这里的单次请求额度（配对研究见页面一）。
- 单股规则使用卡尔曼滤波估计参考价，遵守 T+1 与手工确认的可卖数量。

### 页面五 · 账号管理（仅管理员可见）

- 管理员创建账号时**只填用户名**：新账号处于「待激活」状态、暂时无法登录，密码由使用者本人在登录页选择「首次激活」自行设置，管理员全程不经手、也无从得知。
- 重置密码同理——退回「待激活」并立即撤销该账号全部会话，新密码仍由本人重新设置；禁用后无法登录，可随时恢复。
- 账号清单展示状态（正常 / 待激活 / 已禁用）、角色、创建时间与最近登录；不提供删除，只提供禁用。
- 该页面只对管理员注册为路由，普通账号在导航里看不到，也无法通过页面地址直接打开。
- 系统禁止禁用或重置「最后一个可登录的管理员」，也不会让管理员禁用自己正在使用的账号，避免把所有人锁在门外。

### 页面六 · 模型健康（仅管理员可见）

- **最终留出集只评估一次。** 留出集区间（默认 2024-01-01 起）里冻结模型的动作只在这一次评估里发生，结果落 `models/final_holdout_report.json` 与 `quant_model_final_holdout` 表；同一模型版本再点会被拒绝，确需重评要走 `--force` 并留下「谁在什么时候强制重评」的审计。口径是**评估专用**：日常生产训练照旧按滚动窗口用全量历史重训，否则模型给不出当天的截面结论——这一点与需求文的原始表述不同，详见 `services/model_governance.py` 顶部说明。
- **通过率与门槛失败率。** 每轮训练每个模型每个周期各写一行 `quant_model_validation_log`，页面按近 30 天给出总通过率、分模型 / 分目标的通过率与逐道门槛的失败率；连续 3 次不通过、通过率低于 60%、单道门槛失败率高于 50% 各触发一条告警。样本不足（不足 20 条记录）时如实标注「样本不足」，不拿 0% 冒充。
- **三张漂移表。** 特征漂移（估值、财务因子覆盖率、波动率、换手率、Amihud、市值分布、行业分布）、概念漂移（滚动 Rank IC / ICIR / HAC t 与连续为负天数）、预测漂移（Top 组合行业集中度 HHI、市值分位与分数分布）。PSI 超过 0.1 标「关注」、超过 0.25 标「严重」；滚动 IC 连续 5 个交易日为负、Top 组合行业集中度超过历史 95 分位各触发一条告警。估值维在存在已核验点时历史时，监控原始 E/P、B/P、S/P 分布并汇总最严重项；未接入可靠历史时，页面与库里明确记录原因，不拿当前快照冒充。
- **告警与降级。** 告警写库是必达通道（`quant_model_alerts`），Webhook 与邮件为可选通道、地址与凭据只从环境变量读，默认关闭。出现严重告警时系统**自动**把模型标成 degraded、暂停评分输出并写告警；**回滚与重训必须管理员点击**，回滚会把当前活动版本先归档、按归档目录整体换回，并把操作写进 `quant_model_governance_events`。
- 该页面只对管理员注册为路由，普通账号在导航里看不到；页面内的操作按钮再做一次管理员校验。

## 建模与工程要点

### 2.3.0：历史风格特征、人工调仓与市场状态

- **默认状态**：`ENABLE_BASE_FEATURES=True`，`ENABLE_SIZE_FEATURES=False`、`ENABLE_VALUE_FEATURES=False`。管理员在选股页可请求启用后两项，但生产入模还必须具有当前配置对应的独立验收通过记录；勾选不代表入模成功。默认覆盖门槛为 80%，截面 1%/99% 截尾，再做截面标准化。基础特征开关控制既有量价和扩展因子，显式风格特征单独控制。
- **实际入模**：新增总/流通市值对数、E/P、B/P、S/P。E/P 保留亏损公司的负利润；非正市值、异常净资产或收入记缺失并说明原因。新增风格列不对自身做市值中性化；即使基础因子已中性化，也不能宣称整个预测完全市值中性。模型摘要保留来源、单位、可用时点、覆盖率、排除原因、处理指纹和各模型 `features_used`，健康页区分面板候选与实际入模列。
- **个股因子页**：量价走势评分与五项市值估值特征分开展示，提供报价快照和同日点时历史值、缺失原因及所选模型逐周期的真实 `features_used`；单股快照只供观察，不回填历史、不临时拼接成评分。
- **版本隔离**：协议为 `pit-style-v1`、模型版本为 `2.3.0`；旧权重和旧采集快照不能直接冒充本协议。改变覆盖、截尾、目标、训练窗口、损失或费用等规则，旧验收自动失效。需要重新采集、重建面板并训练。
- **人工任务单**：使用最近完整排名而非页面展示的前 100 行。固定初始止损为含费用平均成本下方 8%，不是每日变化的入场 ATR 止损；趋势退出为收盘跌破 20 日均线。调入要求模型通过、有效同日行情、成交额至少 2000 万元及既有交易计划和交易状态通过。参数集中在 `config/settings.py`。任务单只供下一实际交易日盘前人工复核，不自动下单。
- **市场状态**：每日扫描额外冻结中证 1000 历史，与沪深 300 按共同交易日比较 20 日动量；计算有效样本成交额和换手率的近 60 日分位（至少 20 日），展示申万一级领涨前三与成交额前三。没有净流入数据时只称成交额，不能把成交额称为“吸金”。当前行业映射仅用于当日诊断，不冒充历史点时分类。市场范围不足时明确标为扫描样本；无数据则降级并记日志，不填 0、不臆测成长或红利属性。
- **数据库**：启动时自动执行 `sql/006_market_regime.sql`，在配置的 PostgreSQL `public.quant_market_regime` 保存每日状态及来源、范围、缺失原因；选股页和模型健康页顶部读取最新交易日记录。重复训练旧快照不会挤掉更新日期的记录。数据库连接仍使用现有私有配置，不把密码写入源码。

#### 历史来源与点时口径

已核对 Tushare 官方 `daily_basic` 文档（2026-10-18）：字段 `total_mv/circ_mv` 是万元，`total_share/float_share` 是万股，适配器分别乘 10000 转为元和股；同时保留 `pe_ttm/pb/ps_ttm`。文档说明交易日约 15:00–17:00 更新、单次最多 6000 行、至少 2000 积分，5000 积分档注明无限总量；实际账号频率、权限、积分获取费用和股票可用起止日仍以服务端与授权为准，代码不承诺所有代码有同样长度的历史。接口按股票分年请求，请求成本随股票数和年份数线性增加，不会在每轮训练里自动下载。来源：<https://tushare.pro/document/2?doc_id=32>。

`daily_basic` 的历史日市值先与同日未复权价乘股本对账；其估值是否保留当时原始财报修订版本没有充分证据，因此 `value_pit=False`，原始倍数只供追溯，不直接用于价值特征验收。需要可靠价值特征时，使用 `services.valuation_data.reconstruct_valuation`，输入历史股本事件与原始公告/修订版本：股本含 `ann_date/effective_date/total_shares/float_shares`，财报含 `report_period/ann_date/net_profit_ytd/revenue_ytd/book_equity`，二者均须有来源、采集时间、单位、版本和 `pit_verified=True`。公告当日不使用，下一实际行情交易日才生效；TTM 只组合当时已公开的本期累计、上年全年和上年同期累计。没有可靠历史则保持未接入，禁止用当前股本或当前估值填满过去。

规范 Parquet 历史长表的必填列为 `code/date/source/collected_at/available_at/revision_id/unit/quality/size_pit/value_pit`；`unit` 必须是 `CNY/share`（金额元、股本股），两项 PIT 标记须为布尔值。数值列包括 `market_cap_total/market_cap_float/pe_ttm/pb/ps_ttm/net_profit_ttm/book_equity/revenue_ttm`，缺失可留空但不得以 0 冒充。可提供当时的 `industry/industry_pit` 支持行业暴露验收。原始版本与后续修订追加保存到 `data/panel/valuation/`，同一版本不覆盖原值。

```powershell
# 令牌从环境变量读取；请在本机私密设置 TUSHARE_TOKEN，勿写入仓库。
.venv\Scripts\python.exe -X utf8 style_research.py collect --codes 600000,000001 --start 2015-01-01 --end 2026-10-16
.venv\Scripts\python.exe -X utf8 style_research.py import --file D:\private\valuation_history.parquet

# 导入后在管理员选股页勾选所需风格并重新采集，使估值历史冻结在快照中。
# 下列日期仅示范命令格式；必须选择足够训练历史及未用于调参的新验收区间。
.venv\Scripts\python.exe -X utf8 style_research.py compare --snapshot <采集快照ID> --start 2024-01-01 --end 2024-12-31 --output models/style_comparison.json
.venv\Scripts\python.exe -X utf8 style_research.py accept --snapshot <追加新区间后的快照ID> --comparison models/style_comparison.json --start 2025-01-01 --end 2025-12-31
```

#### 四组对照与独立验收

基础、基础加市值、基础加估值、基础同时加入四组，使用相同股票/日期有效交集、训练窗口、目标、费用与训练标签截尾。报告包含原始标签 MAE/基线、Rank IC、NDCG、分组收益、统一费用后的非重叠期组合收益/回撤以及行业和市值暴露。排序分不能直接当收益计算 MAE，先仅在训练期拟合分数到收益的映射。费用后净值属于研究诊断，尚未模拟涨跌停等成交约束，不可视为可执行收益。

配置选择只使用验证区间；独立验收时仍冻结于原验证起点之前训练，不能把选择期重新作为训练样本。新区间必须严格晚于验证终点；排他区间标记禁止重叠区间反复检验，进程中断也计为已消费。历史股票、特征和成熟标签由数据指纹固定，可追加未来日期但不能静默更换旧数据。文件 `models/style_acceptance.json` 只有在各项门槛、真实入模列与可靠暴露均通过时才允许生产使用；失败和中断均关闭新增特征，保留报告，不修改门槛。代码无法证明人工从未看过某段数据，研究者仍须真实预留新区间。

**当前本地数据限制**：未配置 Tushare 授权且没有可靠估值历史时，采集会明确报未接入，比较/验收入口拒绝空历史。本次功能实现和确定性测试不等于真实收益改善证明；没有实际验收记录时，两类新增风格特征保持关闭。

### 2.2.0：训练标签截尾与健康统计口径

- **预测周期**：统一支持 5、20、30、60 个交易日，标签为股票未来持有期收益减去同期沪深 300 收益；30 日指交易日，不是自然日。`settings.MODEL_HORIZONS` 同时驱动标签生成、训练和个股展示。
- **分位数截尾（Winsorization）**：回归训练先按每折截止日清除尚未成熟的标签，再对训练集每个交易日的有效股票截面分别计算上侧分位数，将超出阈值的标签 Clip 到阈值。默认 `LABEL_WINSOR_UPPER_QUANTILE = 0.99`，可改为 `0.975`；设为 `1.0` 关闭。只截上尾，下尾保持原值；不足 5 只股票的截面跳过，缺失值保持缺失。该规则统一覆盖包括 30 日在内的全部预测周期。
- **示例与边界**：同日 99% 分位数为 35%、某股票训练标签为 120% 时，交给回归器的标签变为 35%。面板原始 `target_*`、`forward_return_*` 不被改写。阈值按训练标签的单位计算，本项目为超额收益；不能将股票绝对收益的阈值直接用于超额标签。
- **评估保持真实**：样本外 MAE、训练中位数基线、Rank IC、NDCG、分组收益及费用后组合回测一律使用原始真实收益。测试标签不参与训练阈值计算，也不通过截尾美化验收。每折和最终拟合都会保存分位数、截尾样本数、占比及跳过截面数。
- **排序标签不截尾**：Clip 会让超过阈值的股票形成并列，保留的是“处于高收益尾部”的粗粒度信息，而非所有极端样本之间的严格名次。因此 LambdaMART / `rank:ndcg` 继续使用原始截面标签生成相关度等级。
- **损失与验收对齐**：回归默认 `REGRESSION_LOSS = "l1"`，分别映射为 LightGBM `regression_l1` 与 XGBoost `reg:absoluteerror`。可设 `l2` 或 `huber` 做对照实验；验收门槛不放宽，MAE 仍须严格优于原始训练标签的中位数基线。
- **缩短冻结验证区间**：样本外从原三折验证的首个测试日起，每 `OOS_RETRAIN_DAYS = 60` 个交易日重新拟合，训练窗口仍最多 750 日，每次均执行标签结束日清除。较原来每折固定预测约一年的方式训练次数更多，耗时也会增加。
- **健康看板分开统计**：累计流程通过率保留全部入选记录，包括未生成指标的失败；另显示指标生成率、已评估记录通过率、最新批次通过率与训练批次数。自动择优先比较验证是否通过，再比较 Rank IC；两种候选的完整门槛指标随 `details.objective_selection` 落库，全部候选通过率独立展示。旧记录没有保存的候选不作推断，不能把入选 rank 的 2/2 理解为所有排序实验都通过。
- **MAE 失败看幅度**：失败明细同时展示模型 MAE、基线 MAE 与相对变化；“4 次均未通过”不等于误差高出 100%。小样本比例只作描述，同一批次的模型与周期也不是独立重复实验。页面可按模型版本筛选，告警仅使用当前版本。
- **比例告警样本量**：总通过率至少需要 20 条记录，单道门槛失败率还要求该门槛自身至少被检验 20 次；不能因排序记录凑够总数，就把仅检验 4 次的 MAE 失败率当成充分证据。历史候选能恢复的结论可补录，未保存的失败门槛保持未知，页面展示指标完整度。
- **摘要与归档一致性**：模型摘要 JSON 与模型、面板一样采用临时文件写入后原子替换，避免硬链接归档被后续保存覆盖；目录和回滚入口校验摘要的 `context_id` 与版本，禁止将不同训练版本直接作为当前版本回滚。最终留出集基线使用冻结模型相同的特征有效样本、训练窗口及成熟标签，页面只展示当前模型版本的留出集报告。
- **新浪备用源市值补齐**：完整分页结果保留 `mktcap`（总市值）与 `nmc`（流通市值），将源端万元统一换算为元，不再在备用源切换后丢失所有市值暴露；缺失仍记为空。股票池内部缓存升为 v2。已经冻结且缺失暴露的旧采集快照不会被原地改写，需要重新采集后才能使用补齐的市值；历史股本和行业仍不是严格点时数据。
- **升级与重新训练**：本次训练协议版本为 `2.2.0`。已有 `2.1.0` 文件和检验历史保留，新版本不会将旧模型冒充为已做截尾的模型；需要在“量化选股”完成新一轮训练，或使用 `python scan_daily.py --force` 运行全流程。已有采集快照可在管理端选择后重新训练，旧面板缺少 30 日标签时需从历史日线重新构建。
- **研究限制仍须如实披露**：截尾和损失调整不保证 MAE 一定改善。缺失市值或行业时，中性化不能宣称已生效；当前股票池回溯仍可能有幸存者偏差。最终留出集只在参数冻结后单独执行，未评估时不得宣称泛化稳健，已用于调参的区间不能重新命名为未见数据。

其中“最终留出集”沿用现有入口名称，当前实现实际验证的是冻结模型的训练截止日隔离与跨期表现；默认 2024 年起的区间可能已经用于日常训练或历史调参，不能自动视为严格独立的未见样本。需要严格最终验收时，应在参数和股票池规则冻结后预留新的、尚未使用的数据区间。历史股票池成分和严格点时股本、行业数据仍需额外数据源，不能通过代码补出。

**排序与回归目标分别验收。** 默认把每个交易日的截面收益按分位映射为 5 级相关度，用 LambdaMART（LightGBM）或 `rank:ndcg`（XGBoost）优化同日排序，`group`/`qid` 为交易日。排序输出是无量纲分数，页面按同日截面百分位展示；只有回归目标给出有量纲的预期超额收益。自动择优同时训练两种目标，先比较是否通过各自全部样本外门槛，再比较 Rank IC；保存入选与未入选候选指标。回归数值校准失败不代表其相对排序完全无效，排序候选也不能因少数入选结果通过就被认定为更稳健。

**滚动窗口重训（Walk-Forward）。** 废弃静态全量训练，每次重训默认只取最近 750 个交易日（约 3 年）的样本，让策略跟上 A 股风格切换。窗口按完整交易日截取，窗口内训练标签的结束日仍必须严格早于测试起日，不会因截断而泄漏未来；设为 0 表示使用全部历史。

**模型治理：留出集、通过率、漂移、降级与回滚。** 训练完成不代表模型仍然可信，因此每轮训练都要留下可复核的检验记录：一次性最终留出集记录冻结模型的跨期检验，只有区间未参与训练和调参时才可作为独立验收；`quant_model_validation_log` 让通过率与「反复卡在哪道门槛」看得出来，三张漂移表让「训练分布与当前截面已经对不上」在系统照常出分之前就被发现。发现严重问题时的处置分两层：系统自动做的只有「标降级 + 暂停评分 + 写告警」（三者完全可逆、不碰生产模型文件），**回滚与重训永远由管理员点击**，并把 before/after 写进 `quant_model_governance_events`。所有治理数据都可以缺失即标注：没有历史分位就说样本不足，没有数据源就写未接入，绝不用 0 或空值冒充一个结论。

**市值与申万一级行业中性化。** 对每个交易日的股票截面，以流通市值对数与行业哑变量做多元线性回归，取残差作为纯净 Alpha 因子，避免模型只学到"买大市值白马"或"追热门板块"。同一天的全部因子使用相同有效样本，覆盖率低于 50% 时自动退回截面 Z 分数因子，并把跳过原因（截面不足 / 因子整体缺失）写入上下文。另补充短期反转（1 日 / 3 日收益）、Amihud 非流动性、量价背离等特征。

**Parquet + DuckDB 列式存储。** 大规模面板不再走 SQLite 行式存储：清洗后的日线、因子面板、市值行业暴露、PIT 财务面板与累积的分钟线统一落盘为 Parquet（zstd 压缩，按 `adjustment=*/code=*.parquet` 分区，先写临时文件再原子替换）。DuckDB 把 Parquet 目录映射成视图做只读即席查询。未安装 duckdb 时退回口径一致的 pandas 向量化实现，并有等价性单测。

**股票池先过生存者偏差关。** 退市、退市整理期与 ST / \*ST 标的在扫描、因子计算与回测之前一律排除，用户自定义代码也不例外。状态取自交易所退市名单与全市场 ST 名单（缓存一天），名单不可用时退回证券简称启发式，并在页面上如实标注当前用的是哪一套。名单覆盖不到的代码不会被默认放行。

**PIT 点时财报多因子。** 财务数据不按报告期结束日、只按交易所实际公告日对齐：DuckDB `ASOF JOIN` 严格取"公告日 < 交易日"的最近一期，公告日当天不生效。每个报告期的「生效日」取计算中实际回看窗口（4 个单季 + 1 个上期累计）内**最晚**的公告日——上一年年报与本年一季报都落在四月，一季报常常**早于**年报披露，只按本期公告日对齐会让 TTM 指标提前引用尚未公开的年报数据。因子覆盖盈利质量（TTM 扣非 ROE、经营现金流净额／净利润）、成长动能（单季营收同比、单季扣非净利同比及其环比变化）与财务健康（Altman Z''，X1 营运资金 / X2 留存收益 / X3 息税前利润 / X4 账面权益）。Z'' 用于非制造业与新兴市场、X4 以账面权益计量，与"不掺入价格"的口径自洽，因此阈值取 1.10 / 2.60 而非原始 Z（1968）的 1.81 / 2.99。报表数据按行业模板取：数据源把定期报告分成通用／银行／保险／证券四套互不重叠的模板，利润表的通用模板覆盖全部行业，但资产负债表与现金流量表的通用模板不含金融板块，故这两张表逐一套模板抓取后合并——只取通用模板会让银行、保险、证券共约 193 只股票静默丢掉这两张表，而覆盖率门控看不出板块级缺失。金融股因此只算能算的部分；银行资产负债表本就没有流动／非流动划分，Z'' 的 X1 与 X3 无从取值，Z 保持为空，这是正确结果而非缺陷。判定为困境区或经营现金流恶化的标的被**一票否决**：在截面标准化之前就整行移出面板，因此这类股票既不会被选中，也不会参与自己所在截面的均值与标准差——拿不到 PIT 财务数据的行是"未知"而非"健康"，不会因为缺失被误杀。

**筹码分布集中度。** 按价格分箱滚动模拟筹码堆积：每个交易日新增成交量按三角分布摊在当日高低价之间，历史筹码按换手率指数衰减。输出 90% 成本区间宽度与获利盘比例——区间越窄说明筹码越集中、套牢盘越少。历史不足 120 个交易日时不出因子，不用短样本冒充稳态筹码。

**日内波动率衰减与订单流不平衡代理。** 把连续竞价切成 8 个 30 分钟区间，逐区间算分钟收益率标准差，对区间序号回归得衰减斜率，并给出「尾盘 30 分钟 / 开盘 30 分钟」波动比。订单流方面，本地没有 L2 逐档快照，用分钟线做两个代理：按涨跌方向拆分的主动买卖量净额，以及成交均价在当日高低区间中的位置（改用「分钟典型价按成交量加权」以避免成交量单位不一致造成的量级漂移）；标准 OFI（Cont 等 2014）已按最优买卖价与挂单量变动的口径实现，接入 L2 后可直接替换。某交易日的日内因子只由该交易日的分钟线计算，不跨日、不插补。

**新增因子按覆盖率门控自动并入。** 三类新因子走同一个下沉层并入排序特征矩阵：整族因子齐全的行占比达到 50% 才纳入训练，否则整族不参与，而不是把大量缺失值塞进特征矩阵让模型去猜；纳入后与基础因子一起做截面 Z 分数标准化，并沿用既有的 Rank IC、HAC t 检验等样本外验收关卡。日内因子受免费分钟线深度限制，本地按日累积落盘以逐步加长历史深度。

**加载阶段异常清洗。** 前复权序列出现超过板块涨跌幅上限 1.2 倍的跳空时按复权口径剔除（上市初期不参与判定）；连续停牌达 20 个交易日标记为长期停牌，不进入当日截面；全天无振幅且触及涨跌停的一字板标记为流动性锁定，不假设成交。清洗只标注与剔除不可信 K 线，不改写原始价格。

## 交易摩擦与风控口径

以下口径属于组合回测引擎本身（`services/portfolio_backtest.py`）。扫描页目前只给排名与评分，不再触发它，但引擎与测试都保留，改由脚本或研究代码直接调用。

组合回测按每日截面把模型排序融合后取前 N 名（默认 20）等权持有，单股仓位上限默认 5%，超出部分留现金、不放大杠杆。撮合严格模拟 A 股制度：

- **T+1**：当日开盘买入最早次日开盘卖出。
- **涨跌停**：开盘一字涨停不假设买入成交，开盘一字跌停不假设卖出成交。
- **停牌**：不交易，按最近收盘价估值。
- **成本**：卖出收 0.05% 印花税，买卖双边各收 0.03% 佣金与 0.1% 滑点，逐笔记录未成交笔数。

打分股票池与撮合股票池强制一致：流动性筛选裁剪股票池后，截面面板同步裁剪，避免排序选中根本没有行情、无法成交的股票。

**模型验证不通过就不输出评分。** 排序目标要求每日 Rank IC > 0.02 且 HAC t > 1.645、NDCG@截面前 20% 高于随机基线 5% 以上、Top 超额为正并优于池均值、Top-Bottom 为正、至少 40 个样本外交易日；回归目标仍按 MAE 中位数基线判定。滚动重训的每一段都会把实际检验数值（`rank_ic`、`ndcg_ratio`、`mae`、`training_dates`、当时生效的验证规则）写进记录，被门槛拦下时能直接看出是哪一条没过、差多少。

## 快速开始

需要 64 位 Python 3.11 或更新版本。Windows 下双击 `run.bat` 会自动创建虚拟环境、安装依赖并启动。

手动执行：

```powershell
py -3 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe -m streamlit run app.py
```

Linux / Nginx 部署见 [deploy/README.md](deploy/README.md)。

首次启动会要求登录，应用会自动补齐初始管理员：**用户名 `admin`，密码 `admin123`**。登录后在侧边栏「修改密码」自行更换。

> `admin123` 是公开写在本文件里的默认口令，知道它的人都能登录并管理账号。请**先改密码再对外提供服务**：未更换前，账号管理页会持续显示告警。密码支持 8 至 128 位，常见弱口令会被拒绝。

后续账号由管理员在「账号管理」页创建，不提供网页注册。也可以继续用命令行：

```powershell
.venv\Scripts\python.exe manage_users.py create alice --temporary
```

`--temporary` 创建的临时密码首次登录后仍会强制修改（至少 8 位）；网页端创建的账号则走「首次激活」，两者互不影响。

## 配置数据库

业务数据（自选、持仓、盘中监控、回测存档、账号）保存在 PostgreSQL 的 `public` 模式，首次启动会自动执行 `sql/` 下的建表脚本，不会覆盖已有数据。

1. 复制模板并填入自己的连接信息：

   ```powershell
   copy config\database.example.json config\database.local.json
   ```

   ```json
   {
     "host": "127.0.0.1",
     "port": 5432,
     "dbname": "quantify",
     "user": "postgres",
     "password": "请填写数据库密码"
   }
   ```

2. `config/database.local.json` 已被 `.gitignore` 忽略，**不会进入版本库**，可以放心写本机口令。仓库里只保留 `config/database.example.json` 这个占位模板。

   - 不复制也能启动：连接项会退回到 `127.0.0.1` / `5432` / `quantify` / `postgres` / 空口令，只适合本机无口令的开发库。
   - 由于该文件不进版本库，每位协作者都需要各自复制一次。
   - `git update-index --skip-worktree` 之类的旧办法不再需要。

3. 也可以改用环境变量覆盖其中任意一项，环境变量优先级更高：

   | 变量 | 含义 |
   | --- | --- |
   | `QUANT_PG_HOST` | 主机 |
   | `QUANT_PG_PORT` | 端口 |
   | `QUANT_PG_DBNAME` | 数据库名 |
   | `QUANT_PG_USER` | 账号 |
   | `QUANT_PG_PASSWORD` | 密码 |

密码只从配置文件或环境变量读取，不写死在源码里，也不会进日志。`config/database.local.json` 不进版本库，仓库里只有上面那份占位模板；数据库不可用时会明确报错，不会退回临时内存假装保存成功。

## 已知限制与免责声明

- **不构成投资建议。** 扫描与策略信号是研究结果，历史回测不代表未来收益。
- 行情接口免费且无 SLA，可能限流、延迟或变更；实时行情、最近收盘行情与缓存行情会被明确区分，过期数据不会用于生成扫描预测。
- 个股行情源提供 PE(TTM)、PB 和市值时，个股页会显示当前快照；估值数据未覆盖的来源会显示缺失，当前快照不代替经点时核验的历史因子。相对行业基准的强弱仍未接入，相对强弱目前只对比沪深 300。
- 股票池过滤用的是**当前**退市与 ST 名单，能在扫描与回测前挡掉当下的问题股，但**无法还原历史时点的成分股**：过去某天它是正常股还是 ST，本地没有历史状态序列，因此回测净值为"本次实际采集股票池"内按模型排序的结果，幸存者偏差只被削弱、未被消除。
- PIT 财务因子的公告日取自巨潮资讯披露日历，财报数值取自东方财富 F10 报表接口。两者口径不一致或接口改版时可能对不齐，此时该期留空而不是回退到报告期，避免静默引入未来函数；因此实际覆盖率受接口可得性影响。
- 金融股（银行／保险／证券）的财务因子中，只有 Altman Z'' 为空：它们的资产负债表没有流动／非流动划分，Z'' 的 X1 与 X3 无从取值。其余因子（TTM 扣非 ROE、经营现金流／净利润、单季营收同比、扣非净利同比及加速）都有数，因为利润表取的是覆盖全部行业的通用模板。Altman Z'' 本就不适用于金融企业，让它留空好过算一个不能解释的数。
- 财务面板按股票分区缓存，已落盘的分区不会因取数口径变更自动重拉。若在「资产负债表与现金流量表补齐金融板块」这一改动之前建过面板，需要显式刷新（`build_fundamental_panel(..., refresh=True)`）才会补上金融股的这两张表。
- 历史市值由"当前流通市值 ÷ 当前价 × 历史收盘价"近似，行业使用当前申万一级分类，均非严格点时数据。
- 筹码分布只用日线的最高／最低／收盘与换手率做三角分布近似，不是真实的逐笔成本分布；免费分钟线单次仅返回最近约 5 个交易日（1 分钟），日内因子的历史深度靠本地逐日累积。
- 日内订单流为**代理指标**，由分钟线按涨跌方向拆分成交量近似，不等同于 L2 逐笔委托流；标准 OFI 虽已实现，但在未接入 L2 盘口前不会被调用。
- 费率按比例近似，未模拟最低佣金、整手与盘口深度；未完整模拟 IPO 特殊涨跌幅与精确分红税。
- 分钟级信号不等同于交易所级高频交易，未接入逐笔行情、委托、撤单或券商回报，不会自动下单。
