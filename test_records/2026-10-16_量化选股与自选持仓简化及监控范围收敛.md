# 2026-10-16 量化选股与自选持仓简化及监控范围收敛

需求来源：`x uqiu.txt`（三条，原文）

```
1.去掉量化选股中的扫描后模拟一个组合，我只需要排名和评分
2.自选和持仓中，对于数字的加减应该是100为单位，并且增加删除字段，需要填的值太多了，简化，盘中监控只监控自选和持仓，其余的不监控
```

## 六、排障轨迹

1. **自定义代码试跑会覆盖共用结论**：试跑若走 `save_scan_result`，`data/last_scan.json` 会被换成几只股票的结果，其他账号打开页面就看不到全市场排名——正是需求 3 要防的事。对策：试跑改走内存 `build_payload(result)`，不落盘，并补 `test_preview_payload_matches_the_saved_file_field_by_field` 防止两条路径字段分叉。
2. **Streamlit 禁止 expander 嵌套**：持仓录入表单原本整体套在 `st.expander("录入一笔持仓")` 里，再加内层「更多（可选）」会直接抛 `Expanders may not be nested inside other expanders`。对策：外层 expander 换成表单内的 `st.subheader("录入一笔持仓")`（表单本身已有卡片样式）。
3. **`unittest discover -t .` 不可用**：`ImportError: Start directory is not importable: 'D:\github\quant\tests'`。对策：去掉 `-t .`，用 `-s tests -p "test_*.py"`。
4. **股数步长的边界**：`number_input(step=100)` 若同时把 `min_value` 抬到 100，历史送股/配股产生的零股在编辑表里会被判为非法值。对策：录入表单用 `min_value=100` 保证按整手建仓；两张编辑表保持 `min_value=1`/`min_value=0`、只给 `step=100`，历史零股仍可改可存。
5. **浏览器验证未完成**：Playwright MCP（`connect ECONNREFUSED 127.0.0.1:9222`）与 Chrome DevTools MCP（`Could not connect to Chrome`）当时均不可用，步长按钮的实际取整行为未能实机确认。因此实现选择了在「按 min_value 取整」与「按 0 取整」两种行为下都安全的取值，未依赖任一具体行为。

## 七、明确保留、需要知情的三点

1. `include_backtest`（逐股历史回放）**未删**——需求 1 说的是「扫描后模拟一个组合」，逐股回测是另一件事。
2. 录入表单的股数 `min_value=100`，因此从表单无法新建 100 股以下的零股；编辑表仍可修改并保存历史零股。
3. `services/intraday_strategy.py::analyze_intraday_pair` 已不被应用代码调用，但保留为可独立调用的研究函数，其用例（含 `test_pair_does_not_bypass_borrow_confirmation`）继续保留。
