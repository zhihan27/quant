## 1. 问题 1：302 号段漏登记

### 1.1 报错与误判

用户看到的是：

```text
股票列表获取失败：股票池分页不完整：源端总数 1453，去重后仅 1452 只；拒绝缓存不完整股票池。可切换为用户自定义代码。
```

页面把原因归到「分页不完整」，但**分页本身是完整的**。真实原因是创业板启用了新号段。

### 1.2 定位过程（含一次被证据推翻的初始判断）

先按报错字面怀疑 `_map_universe_rows` 的 `drop_duplicates` 撞码，实时抓一份源端数据后否定：

```text
源端 total = 1453 | 唯一代码 = 1453        <- 没有重复，去重不是原因
code
300    977
301    475
302      1     <- 被白名单丢掉的就是这一只
白名单 ('300','301') 保留 = 1452 | 被丢弃 = 1
```

再翻分页日志，逐页齐全、无缺页：

```text
universe page scope=chinext page=1..14 rows=100, page=15 rows=53
100 * 14 + 53 = 1453 = source total
```

至此确认：**分页完整，是号段白名单过时**。`302132` 不在 `("300", "301")` 里，被前缀过滤丢掉后，代码又拿"过滤后的数量"去和"过滤前的源端总数"比对，于是报成"分页不完整"——一个错误的诊断信息掩盖了真正的原因。

### 1.3 漏登记共 10 处

| # | 位置 | 用途 | 不修的后果 |
| --- | --- | --- | --- |
| 1 | `market_data.py` scope 过滤 | 股票池范围 | **扫描直接报错**（用户遇到的） |
| 2 | `market_data.py` 备用源 scope 过滤 | 同上 | 东财失败后切备用源同样漏股 |
| 3 | `market_data.py` `_valid_universe_cache` | 缓存有效性校验 | 缓存被误判无效、反复重取 |
| 4 | `market_data.py` `_filter_universe_rows` | **代码有效性白名单** | 302 被静默判为无效代码剔除，不报错 |
| 5 | `scanning.py` 主板过滤 | 排除创业板 | 302 股被误当主板 |
| 6 | `scanning.py` 创业板过滤 | 板块内筛选 | 302 股进不了创业板扫描 |
| 7 | `data_cleaning.py` `price_limit_rate` | 涨跌停幅度 | **302 股按 10% 算，实际 20%** |
| 8 | `data_cleaning.py` `_limit_series` | 逐行涨跌停序列 | 同上 |
| 9 | `pages/2_量化选股.py` | 页面显示涨跌停 | 显示错误 |

第 4 处是在第一轮修复**之后**、用实地探针才发现的：改完 1–3 后创业板返回 1367 只，号段分布仍是 `{'300': 897, '301': 470}`，**302 依旧为空**。追下去才看到 `_filter_universe_rows` 里还有一份独立的六位代码正则 `(?:000|001|002|003|300|301|600|601|603|605|688|689)\d{3}`。补上 302 后返回 1368 只，302 号段样本 `['302132']` 出现——**恰好找回那一只**。

### 1.4 修复

新增单一出处，其余引用它：

```python
# config/settings.py
# 交易所号段。2026 年创业板启用 302 号段，新股发行还会继续扩充号段，
# 因此股票池过滤、缓存完整性校验与涨跌停制度判定统一引用这一份定义。
BOARD_PREFIXES = {
    "main": ("00", "60"),
    "chinext": ("300", "301", "302"),
    "star": ("688", "689"),
    "bj": ("43", "83", "87", "92"),
}
# 涨跌停制度只看交易所大类：北交所涵盖 43/83/87/92 起首的 4x/8x 全部号段，
# 比股票池过滤用的具体号段更宽，故不并入 BOARD_PREFIXES。
BSE_LIMIT_PREFIXES = ("4", "8", "92")
```

同时修正被误导的那句诊断——分页完整性针对的是**源端全量**，必须拿过滤号段**之前**的去重数比对：

```python
# 分页完整性针对源端全量：必须拿过滤号段之前的去重数比对。
# 用过滤后的数量比对，会让任何一个未登记的号段被误报成“分页不完整”。
if source_total is not None and source_unique_codes < source_total:
```

第 4 处（代码有效性正则）是**另一种粒度**（按三位号段族逐一枚举，含 001/002/003、601/603/605），无法从两字符的 `main` 前缀干净推导，因此保留字面量，改由一条断言把耦合显式化：`test_board_prefixes_are_all_valid_codes` 会遍历 `BOARD_PREFIXES` 里的每个号段，断言它都能过白名单。下次再有人只改 settings 不改这里，测试会直接失败，而不是静默少一批股票。

## 2. 问题 2：302 股票的涨跌停被按 10% 计算

这条不报错，是本次最隐蔽的一项。`_limit_series` 得到的 `limits` 同时喂给三处判定：

```python
locked_up = flat & returns.ge(limits * 0.98) & previous_close.gt(0)
locked_down = flat & returns.le(-limits * 0.98) & previous_close.gt(0)
gap = returns.abs().gt(limits * settings.ADJUSTMENT_GAP_TOLERANCE + 0.01)   # 1.2 倍容差
```

限值取 0.10 而非 0.20 时：

- `gap` 阈值从 0.25 降到 0.13，**一根正常的 +20% 涨停会被判成"前复权异常跳空"**，整行移出 `is_usable`，不进因子、不进标签、不进回测——既不报错也不提示；
- `locked_up` 阈值从 0.196 降到 0.098，**任何一根无振幅的 +10% 平盘会被误判为一字涨停**，回测里被当成买不到。

回归用例断言的就是第一条：

```python
bars = _bars([10.0] * 6 + [12.0, 12.0, 12.0])
cleaned, report = clean_daily_history(bars, code="302132", adjusted=True)
self.assertAlmostEqual(float(cleaned.loc[6, "limit_rate"]), 0.20)
self.assertFalse(cleaned.loc[6, "is_adjustment_gap"])
self.assertTrue(cleaned.loc[6, "is_usable"])
self.assertEqual(report["adjustment_gap_bars"], 0)
```

## 3. 问题 3 / 4：个股分析页

### 3.1 「分析所选股票」是空动作

原代码：

```python
selected_label = st.selectbox("匹配结果", labels)      # 无 key，每次 rerun 都重置
selected_code = selected_label.split()[0]
if st.button("分析所选股票", type="primary"):           # 只写会话，不分析、不跳转
```

该按钮既不拉数据也不切页，唯一作用是把自己已经算出来的 `selected_code` 存进会话，而下方才是真正干活的「运行分析」。用户因此要连点两次才看到结果。修复为下拉框选中即生效，并补上 `key="match_selection"`；同时在每次重新搜索时 `pop` 掉该 key——候选列表换了之后，旧的选中值在新列表里不存在，Streamlit 只能回退到第一项。

### 3.2 成交量/成交额截断

`st.columns(7)` 在常规内容宽（约 1400px）下每列不足 200px，`st.metric` 的数值用 `text-overflow: ellipsis` 截断。按 1.75rem 字号估：

| 指标 | 原文案 | 约需宽度 | 七列时可用 | 结果 |
| --- | --- | --- | --- | --- |
| 成交额 | `1,234,567,890 元` | ≈270px | ≈180px | 截断 |
| 成交量 | `10,000,000 手` | ≈220px | ≈180px | 截断 |

改为两行（4 + 3）并让成交额按亿元显示：`12.35 亿元` ≈150px，落在 ≈350px 的列宽内。第二行同样用 `st.columns(4)` 只放 3 个指标，让两行栅格对齐。

## 4. 两条只作解释、未改代码的问题

**「开始模拟并保存结果」**：按下会跑一次滚动窗口的**组合回测**（默认按评分取前 N 名等权持有、T+1、扣印花税/佣金/滑点），结果写进回测存档，可在页面三回看。它不会买卖任何东西，只是"把这套规则放回历史上跑一遍"。

**「当前股票不在已训练截面内，或日线已更新，请重新扫描股票池」**：横截面排序模型是**按交易日整片训练**的，预测时必须落在某个已训练的交易日内。出现该提示意味着这只股票的代码不在上次扫描的股票池里，或它的最新日线日期与已训练截面的 `reference_date` 对不上（收盘价也参与比对）。修完 §1 之后，302 股票此前根本进不了股票池，这一类提示会明显减少；正常范围内的解决办法就是重跑一次扫描。
