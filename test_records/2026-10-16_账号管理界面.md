# 2026-10-16 管理员账号管理界面

需求原文（用户原话）：

> 管理员登录需要有界面可以管理账号密码，支持管理员创建用户，首次创建让别人输入密码，并且管理员支持重置密码，即再次让别人手动输入，另外提供初始帐号管理员，即admin，密码也是admin123

补充口径（用户原话）：

> 密码不需要12位，8位即可

三方会审后由用户确认的三项设计决策：

| 决策点 | 用户选择 | 实现方式 |
| --- | --- | --- |
| 密码下发方式 | 账号待激活，使用者自行设密码 | 管理员只填用户名；账号 `activated=false`，登录页「首次激活」由本人设密码 |
| 初始 admin/admin123 | 不强制，立即可用 | 启动时自动补齐管理员，不强制改密；未更换前页面持续告警 |
| 账号删除 | 只禁用，不删除 | 无删除入口，只有禁用 / 恢复 |

## 4. 排障轨迹

### 4.1 `switch_page` 找不到账号管理页

**现象**：改动路由后 `tests.test_auth.AuthInputTests.test_all_routes_require_login_without_database` 报错——

```text
ValueError: Could not find a navigation page for 'D:\github\quant\pages\5_账号管理.py'.
```

**定位**：报错本身就是新安全性质生效的证据——`app.py` 只在管理员会话下才 `st.Page(...)` 注册该页，未登录时 `Known pages` 里只有四个业务页。

**处置**：不改路由（改了才是漏洞），改测试。抽出模块级常量 `BUSINESS_PAGES` 供三处循环复用，并新增两条断言：未登录时该页 `switch_page` 必须抛 `ValueError`；普通账号登录后同样抛 `ValueError`，管理员登录后能正常渲染并出现「初始密码」告警。

### 4.2 一度把 `require_login()` 提到了 `st.navigation()` 之前

**现象**：`test_all_routes_require_login_without_database` 断言 `[] != ['量化研究登录']`。

**根因**：`require_login()` 先 `st.stop()` 会让 `AppTest` 拿不到已注册的页面，`switch_page` 落到空运行。

**处置**：恢复 `st.navigation(...)` 在前的顺序，改用 `position="sidebar" if account else "hidden"`；首屏不连库的性质由 `current_account()` 里的 `if not token: return None` 短路保证（测试对 `get_auth_service` 打了 `side_effect=AssertionError` 兜底，一旦连库即失败）。

### 4.3 已知的运维影响（**需求方需知悉**）

`ensure_initial_admin()` 的规则是「只要系统里还没有任何管理员，就把 `admin` 补成管理员、并下发初始口令 `admin123`」。真实库里 `admin` 账号**已经存在**（2026-10-15 18:28 创建，非管理员），因此**下一次真实启动时该账号会被提升为管理员，其密码哈希被覆盖为 `admin123`，已有会话被注销**——原来那个密码将不再可用。

这与需求「初始帐号管理员，即admin，密码也是admin123」「不强制，立即可用」一致，故按此实现；但属于对存量账号的一次性覆盖，记录在此备查。若希望保留原密码，只需把 `services/auth.py::ensure_initial_admin` 里那段 `UPDATE ... password_hash=...` 改为只写 `is_admin=true`。

`ensure_initial_admin()` 由 `@st.cache_resource` 包裹的 `get_auth_service()` 调用，每进程至多执行一次；且一旦存在管理员即走只读分支返回，不会反复覆盖已修改的密码。

### 4.4 未处理项（沿用上一轮数据库评审的结论）

`services/database.py::save_quotes` 只跳过 `price is None`，没有拒绝 `price <= 0`，而 `quant_quote_snapshots.price` 带 `CHECK (price > 0)`；调用点 `services/intraday_monitor.py` 未包 `try/except`。本轮未改动（不在本次需求范围内，且属行为变更）。
