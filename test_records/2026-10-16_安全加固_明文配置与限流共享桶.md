## 2. 问题 3：共享来源桶导致的全局锁死

**修复前**：`auth_ui.client_address()` 在非代理模式下返回常量 `"direct"`，代理头异常时返回常量 `"proxy-missing"`。`_reserve_login` 用它构造 `ip:<摘要>` 桶（30 次 / 900 秒），于是**全体用户共用一个桶**——任意一人发 30 次失败登录，15 分钟内所有人都无法登录。同一缺陷还存在于另外两处常量地址：`activate_user(username, "activate")`（未登录可达）与 `change_password(..., "password-change")`。

**修复思路**：来源限流需要真实的客户端标识。拿不到时**不启用该桶**，而不是退化成共享桶。直连模式的兜底变成 `global`（120 次 / 60 秒，锁死窗口从 15 分钟降到最多 60 秒）与 `user`（5 次 / 900 秒，逐账号防爆破，未改动）。

```python
# auth._reserve_login
limits = [("global", 120, 60)]
if address:                                    # 仅在能确认真实来源时才启用
    limits.append(("ip:" + token_digest(address), 30, 900))
limits.append(("user:" + token_digest(username), 5, 900))
```

`activate_user` / `change_password` 增加 `address: str = ""` 形参（带默认值，兼容既有调用与测试），由 `auth_ui` 传入 `client_address()`。代理模式（生产）下三种入口现在都拿到真实 IP，行为较修复前更严格。

**验证**：用一次性随机模式隔离，避免污染真实库。

| 场景 | 桶集合 | 断言 |
| --- | --- | --- |
| `_reserve_login("probe", "203.0.113.9")` | `global`、`ip:<摘要>`、`user:<摘要>` | 真实来源仍产生 ip 桶 |
| `_reserve_login("probe", "")` | `global`、`user:<摘要>` | 不得出现共享 ip 桶；user/global 仍生效 |
| 直连模式下先发 30 次失败登录，再用正确口令登录另一账号 | — | **登录成功**（修复前会被共享桶拦下） |

第三条是关键复现：修复前该场景返回「登录尝试过于频繁」。

## 3. 问题 5：DuckDB 视图路径拼接

**修复前**：`services/panel_store.py` 三处 `f"... read_parquet('{glob}')"`，以及视图名 `CREATE VIEW {name}`。`glob` 源自 `settings.PANEL_DIR`（项目根下固定路径），不由用户输入决定，故审查判定**当前不可利用**，但属于接入外部输入即成注入的写法。

**关键约束**：DuckDB 的 `CREATE VIEW` **不支持预编译参数**，先验证再决定做法：

```
literal OK -> (2,)
param FAIL: BinderException  Binder Error: Unexpected prepared parameter. This type of statement can't be prepared!
escape OK  -> (2,)
```

因此不能参数化，正解是字面量转义：

```python
def _duckdb_literal(value: str) -> str:
    """转义 DuckDB 字符串字面量；CREATE VIEW 不能被预编译，只能安全拼接。"""
    return "'" + value.replace("'", "''") + "'"
```

视图名同步加双引号标识符引用。

**验证**：构造目录名含单引号的 `panel' with quote`，写入日线后建视图并查询。

```
注册视图: [... 'fundamentals', 'history' ...]
history 行数: 2 | fundamentals 行数: 1
转义后缀: ote\code=*.parquet''); DROP VIEW history; --'
```

含引号路径下视图正常创建与查询，注入载荷中的单引号被双写。
