## 二、性能缺陷：`attach_chip_factors` 的平方级字符串扫描

### 2.1 现象与消息来源

页面上的「正在汇总分钟线」来自 `services/intraday_factors.py:251`（本地分钟线汇总循环）。
**这条消息本身不是卡点**：本机 `data/panel/` 下根本没有 `intraday` 目录（只有
`exposures` / `history` / `universe`），该循环对每只股票都是快速落空。

真正长时间静默的是紧随其后的 `services/ml_pipeline.py::build_market_panel`，它调用
`services/chip_factors.py::attach_chip_factors` 把筹码因子并进面板。旧写法在**逐股循环里**
对整块面板做一次字符串掩码：

```python
mask = result["code"].astype(str).str.zfill(6).eq(code)   # 全表 600 万行字符串扫描
aligned = result.loc[mask]                                # 又一次整块复制
```

面板是「全市场 × 全历史」的长表（约 5000 只 × 1200 天 ≈ 600 万行），于是每只股票都要
把 600 万行扫一遍、再复制一遍。

### 2.2 量化证据

真实面板上的实测（上一轮审查时逐只计时）：**940.7 ms/只**（仅掩码）、
**1000.5 ms/只**（掩码 + 2 次 `.loc` 写回），折合 5370 只约 **89.5 分钟**。

可复现的对照基准（本文件附录脚本，20 万行 × 500 只，按行数线性外推）：

```
面板规模：200,000 行 × 500 只（真实全市场是 5000 只 × 1200 天 ≈ 600 万行）
旧写法：逐只 astype(str)/zfill/eq 全表扫描 → 32.6 ms/只，全市场 5370 只折合 2.9 分钟
新写法：一次性建「代码 → 行位置」映射 → 0.10 秒（只算一次）
新写法：循环内按位切片 → 0.005 ms/只，全市场折合 0.00 分钟
```

20 万行 → 600 万行是 30 倍，32.6 ms × 30 ≈ 978 ms/只，与实测 940.7 ms/只吻合，
说明这条基准是可外推的，不是合成数据造成的假象。

### 2.3 修法

循环期间 `result` 的代码列与行序都不变，于是把「代码 → 行位置」一次性算好，
循环内只做按位切片；写回也不再逐只 `.loc` 复制整块，而是先在 numpy 缓冲里按位写入、
最后整体回填一次：

```python
panel_codes = result["code"].astype(str).str.zfill(6).to_numpy()
positions_by_code = pd.Series(np.arange(len(result)), index=panel_codes).groupby(level=0).indices
panel_dates = pd.DatetimeIndex(pd.to_datetime(result["date"]))
buffers = {column: result[column].to_numpy(dtype=float, copy=True) for column in CHIP_FACTOR_COLUMNS}
...
slots = positions_by_code.get(str(code).zfill(6))
aligned = values.reindex(panel_dates[slots])
for column in CHIP_FACTOR_COLUMNS:
    buffers[column][slots] = aligned[column].to_numpy()
...
for column in CHIP_FACTOR_COLUMNS:
    result[column] = buffers[column]
```

修后逐股开销≈0（0.005 ms/只），剩下的 46~61 ms/只是 `chip_distribution` 本身的计算，
全市场约 **5.5 分钟**（89.5 → 5.5 分钟）。

### 2.4 另一半成本：前复权历史必然全量重取

同一次扫描里，**「正在汇总分钟线」之前**还有一段很长的网络等待，日志可以看到：

```
$ ls logs/
daily_scan.log  market_data.log          # 没有 console.log
$ ls data/panel/history/adjustment=qfq | wc -l
5370
```

`services/market_data.py::get_history` 的 `full_refresh = (adjusted or not old_rows or ...)`：
**只要请求的是前复权序列就必然全量重取 1200 根日线**，而
`MAX_CONCURRENT_REQUESTS = 1` + `REQUEST_INTERVAL_SECONDS = 0.25` 把速率压在约 4 请求/秒，
5370 只的固定下限约 **22 分钟**。上一轮审查时在 `logs/market_data.log` 里看到 8650 条请求
横跨 2026-10-15 15:31 → 2026-10-16 16:57，其中 15 点这一小时 5713 条，
`data/panel/history/adjustment=qfq` 下 5370 个文件全部在当天 16:36~16:57 被重写（约 300 个/分钟），
日志最后一行停在 16:57:43。

**所以「卡在正在汇总分钟线」的观感 = 前面 20 分钟以上的全量重取 + 后面 89 分钟的面板并入，
而进度提示正好停在这两段之间。**

## 六、排障轨迹

### 6.1 `discover` 在本仓库不可用

```
ImportError: Start directory is not importable: 'D:\github\quant\tests'
```

`tests/` 没有 `__init__.py`（也不应加），改为显式枚举模块名，见 §三 第 3 条。

### 6.2 Bug 2 的修法把存量用例打红了（这是修对了的信号）

修完 Bug 2 后，`test_scan_writes_all_three_drift_tables_and_the_validation_log` 报：

```
AssertionError: Lists differ: ['模型归档失败，本版本不会出现在回滚候选里：
FinalHoldoutError: 归档失败：活动文件缺失 model, summary, panel。'] != []
```

原因：该用例的 `_scan_context()` 只**造**了一个 context 字典，而真实链路是
`train_market_context(persist=True) → save_context（落盘三个文件）→ after_scan`。
归档校验「活动文件是否存在」是对的，**病的是替身**。修法：加 `_scan()` 辅助方法，
先 `_publish()` 真实落盘再跑治理，四处 `after_scan` 直调改写为 `_scan`。
连带把 `test_severe_drift_...` 的断言从「活动版本还是 ctx-good」改成
「活动版本还是**本轮产出** ctx-scan 且 ctx-good 归档目录仍在」——原断言在引入真实落盘后
不再成立，而它要表达的意思（降级不换生产模型）没变。

## 七、结论与遗留

1. 6 个缺陷全部修复，其中 Bug 1 在本机环境下是**每轮扫描必触发一次误报降级**的高频故障，

## 附录：性能对照基准脚本

```python
"""对照测量：把筹码因子并入面板时的逐股定位开销（旧写法 vs 新写法）。"""
import time
import numpy as np
import pandas as pd

ROWS_PER_CODE, CODES = 400, 500
rng = np.random.default_rng(7)
codes = [f"{600000 + i:06d}" for i in range(CODES)]
panel = pd.DataFrame({
    "code": np.repeat(codes, ROWS_PER_CODE),
    "date": np.tile(pd.date_range("2024-01-01", periods=ROWS_PER_CODE, freq="B"), CODES),
})
print(f"面板规模：{len(panel):,} 行 × {CODES} 只（真实全市场是 5000 只 × 1200 天 ≈ 600 万行）")

start = time.perf_counter()
for code in codes:
    mask = panel["code"].astype(str).str.zfill(6).eq(code)
    slots = panel.loc[mask]
elapsed = time.perf_counter() - start
print(f"旧写法：逐只 astype(str)/zfill/eq 全表扫描 → {elapsed / CODES * 1000:.1f} ms/只，"
      f"全市场 5370 只折合 {elapsed / CODES * 5370 / 60:.1f} 分钟")

start = time.perf_counter()
panel_codes = panel["code"].astype(str).str.zfill(6).to_numpy()
positions = pd.Series(np.arange(len(panel)), index=panel_codes).groupby(level=0).indices
one_time = time.perf_counter() - start
print(f"新写法：一次性建「代码 → 行位置」映射 → {one_time:.2f} 秒（只算一次）")
start = time.perf_counter()
for code in codes:
    slots = positions.get(code)
    _ = panel_codes[slots]
per_code = time.perf_counter() - start
print(f"新写法：循环内按位切片 → {per_code / CODES * 1000:.3f} ms/只，"
      f"全市场折合 {one_time / 60 + per_code / CODES * 5370 / 60:.2f} 分钟")
```
