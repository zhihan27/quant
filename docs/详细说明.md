# A 股量化分析与选股研究系统

这是一个本地 Streamlit 研究工具，提供个股分析、量化扫描、统计套利研究和带交易成本的历史实验。股票池和行情优先使用东方财富公开接口，个股行情和日线设有新浪财经备用源；页面显示数据源、行情状态和采集时间。行情源未提供独立成交时间时，程序不会把采集时间冒充成交时间，也不会把过期缓存标为实时行情。

## 环境与启动

账号登录及 Linux/Nginx 部署说明见 [deploy/README.md](deploy/README.md)。账号必须通过 `manage_users.py` 在终端创建，所有业务页面要求登录；临时密码首次登录后必须修改。

建议使用 Windows 64 位 Python 3.11 或更新版本。首次启动会创建 `.venv` 并安装依赖：

```bat
run.bat
```

也可以手动执行：

```powershell
py -3 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe -m streamlit run app.py
```

## 数据与限制

- 行情接口免费且未提供 SLA，可能限流、延迟或变更。系统按沪、深、北交易所股票范围分页拉取列表，每页最多 100 条，逐页读取并核对源端总数、去重代码数和沪深京覆盖；全市场至少通过 4,000 只及北交所覆盖校验。分页不完整或备用列表低于阈值时明确报错，不会退回首屏。
- 股票池优先东财完整分页，失败后直接读取新浪沪深京列表，先取源端总数，再按80只一页完整拉取；每页独立超时，避免用35秒子进程限时中断整批约70页任务。新浪数据须通过源端总数、唯一代码和北交所覆盖检查。AkShare仅作后续备用，未通过规模校验的首屏或部分列表均不用于全市场扫描。
- 股票池排除 ST、*ST、退市整理、无效代码、无有效价格和零成交量股票。新股保留在池中，但历史样本不足时不生成模型预测；停牌或没有有效行情的个股单独列入失败/排除结果。
- 个股快照优先使用东方财富，新浪财经作为备用；日线优先使用东方财富，备用使用 AkShare 新浪日线。统一为六位代码、人民币价格、日历日期和 OHLCV 字段，成交量统一为手、换手率统一为百分比；模型默认使用前复权日线，回测使用不复权日线。不同数据源的复权和字段差异会在来源状态中标明。
- 网络请求优先遵循系统 HTTP/HTTPS 代理环境变量。公开的东财及新浪行情域名遇到 `ProxyError` 时，使用独立会话尝试直连；成功后同域名五分钟复用直连，不修改系统代理及环境变量。`QUANT_NETWORK_MODE=proxy` 可强制仅走代理，`direct` 可让这些行情域名优先直连，默认 `auto`。完整分页及覆盖校验保持启用，连接路由和完整异常写入日志，页面只展示简短故障原因。
- 实时行情、最近收盘行情和缓存行情明确区分。行情源没有稳定逐股成交时间时，仅显示接口采集时间；过期股票池/报价标注非实时，过期历史数据不用于生成扫描模型预测。
- SQLite 缓存在 `data/quant.db`。实时快照缓存 30 秒、股票列表 15 分钟、日/周 K 线 6 小时。缓存回退会显示过期状态。
- 大规模面板数据不再依赖 SQLite 行式存储：逐股清洗后日线、因子面板与市值行业暴露统一落盘为 Parquet（`data/panel/`，zstd 压缩，先写临时文件再原子替换），目录按 `adjustment=*/code=*.parquet` 分区。逐股/整面板回读走 pyarrow；DuckDB 负责把 Parquet 目录映射成视图做只读即席查询，并用窗口函数完成每日截面 Z 分数与 `groupby` 聚合；未安装 duckdb 时截面标准化退回口径一致的 pandas 向量化实现（有等价性单测），不会静默给出不同结果。列式面板属于派生产物，写入失败只在状态中记录，不影响已取得的行情。
- 加载阶段即执行行情清洗：前复权序列出现超过该板块涨跌幅上限 1.2 倍的价格跳空时按复权口径异常剔除（上市前 6 根 K 线及新股无涨跌幅限制期不参与判定）；连续停牌达到 20 个交易日标记为长期停牌，不进入当日截面；全天无价格振幅且已触及涨跌停的一字板标记为流动性锁定，不假设成交，但仍按最近收盘价参与估值。清洗只标注与剔除不可信 K 线，不改写原始价格。
- 日线默认前复权用于图表和因子；回测使用不复权日线。相对强弱目前只对比沪深 300，行业基准未接入。基本面历史披露数据未接入，所以估值、盈利质量和点时财务因子不参与评分。
- SQLite 保存股票池、逐股历史 K 线、接口请求事件及历史同步状态。不复权日线按最近 K 线日期增量更新，并用独立时间戳每周完整替换；前复权日线刷新时总是完整替换，旧版历史缓存已隔离；失败股票下次扫描补拉，已成功股票复用本地数据。请求采用连接/读取超时、有限重试、指数退避、并发 1 和请求间隔限制。网络断开后已成功历史数据不会丢失。
- LightGBM 与 XGBoost 默认按交易日汇总股票池训练**排序目标**（LambdaMART / `rank:ndcg`），把选股定义为每个交易日截面内的优胜劣汰排序，避免回归目标在全市场普涨时给出全线看多的正向偏置；可选“自动择优”同时训练排序与回归两种目标并按样本外 Rank IC 选择，也可显式切回 `regression` 回归目标。排序目标的输出是无量纲的相对排序分，只能按同日截面百分位解读，页面上不会把它当成预期超额收益；只有回归目标才给出有量纲的预期超额收益。特征和预测在同日股票截面内做Z-score；缺少足够截面、依赖或验证失败时不输出预测评分。排序模型按每日截面的 NDCG@前20% 与随机基线之比判定是否通过验证，回归模型仍按 MAE 中位数基线判定。模型预测不换算为绝对价格；规则参考价由ATR计算，不代表实际成交价。
- 每次重训默认只使用最近 750 个交易日（约 3 年）的样本做滚动窗口，使策略能跟上 A 股风格切换；窗口按完整交易日截取，窗口内训练标签的结束日仍必须严格早于测试起日，不会因截断而泄漏未来。扫描页可把窗口改为 0 表示使用全部可用历史，也可按需求调整长度。
- 扫描时可启用市值与申万一级行业中性化：对每个交易日的股票截面，以流通市值对数与行业哑变量做多元线性回归，取残差作为纯净 Alpha 因子，回归后残差与市值对数、行业均值的相关性低于 1e-6。历史市值由“当前流通市值 ÷ 当前价 × 历史收盘价”近似，行业使用当前申万一级分类，两者都不是严格点时数据；同一天的全部因子使用相同的有效样本，覆盖率低于 50% 时自动退回截面 Z 分数因子，并把跳过原因（截面不足或因子整体缺失）写入上下文。
- 扫描和策略信号是研究结果，不构成投资建议。回撤和夏普基于包含空仓、费用和未平仓市值的逐日净值，无法退出的头寸跨测试分段保留；免费数据接口、复权方式、交易制度和成交模拟均有误差，历史样本外结果不保证未来收益。

## 页面

1. 个股分析：代码/名称搜索、行情状态、日/周 K 线、因子、模型验证、ATR 交易参考、回测和配对研究。
2. 量化选股：完整扫描所选股票池，展示实际股票总数、有效/排除数量、更新时间和逐股历史请求状态；结果仅限制展示行数，不限制扫描数量，可以跳转到个股分析。扫描前可选择训练目标（排序/回归/自动择优）、滚动训练窗口和是否启用市值与行业中性化；也可勾选在同一轮扫描后运行 Top-N 组合回测，页面展示组合与基准净值、选股数、单股仓位上限、换手率、费用拖累、未成交笔数，以及每笔成交和每段训练窗口的明细。
3. 自选与持仓：自选增删及监控开关；按批次录入和编辑买入日期、价位、股数、可卖股数、费用和备注；汇总成本与带源时间的参考浮盈亏。
4. 盘中监控：设置3至60秒快照轮询、30至300秒分钟线同步及配对代码；展示行情源时间、真实采集耗时、心跳、卡尔曼参考价和协整研究提醒。

## 验证

在项目目录运行 `.venv\Scripts\python.exe -X utf8 -m unittest discover -s tests -v`。单元测试使用本地构造数据验证计算逻辑，不把构造数据展示为市场结果。真实行情功能需要网络访问东方财富接口；网络失败时会显示错误或注明使用缓存。


## 策略与回测口径

- 根目录启动脚本和 app.py 已统一进入本项目；旧版未经验证的分钟套利接口已停用。当前配对模块为日频研究，不提供高频自动下单。
- 新增的分钟研究使用独立模块，不调用旧分钟接口。当前秒级快照和一分钟信号不等同于交易所级高频交易，未接入逐笔行情、委托、撤单或券商回报。
- 综合评分为40%同日截面因子分加60%通过验证的模型百分位，取消绝对收益的tanh映射。模型必须同时通过MAE中位数基线、每日Rank IC及其HAC显著性、Top/Bottom分组收益检验；未通过时仅显示因子观察，不给预测分。
- 有效入场同时要求模型通过验证、预期超额收益为正且截面Z分数为正、收盘价高于20日均线、20日均线高于60日均线、量能达标、历史及行情有效。参考区间以完整收盘价计算，次日开盘不在区间内就不假设成交。
- 默认回测每20日用此前历史重新训练及验证模型，预测5/20/60日模型中的20日模型用于交易；验证标签清除跨区间重叠。固定规则基线须显式选择 `strategy="trend"`，其结果不能代表模型策略。
- 止盈止损使用不复权价格撮合；开盘跳空按开盘价计，盘中触价须在当日范围内。同日止盈止损均触发时按止损优先。趋势或移动退出在收盘确认，下一交易日评估；买入当天不卖出。
- 回测持仓最多20日，无法成交继续持有并估值，不在分段边界凭空清仓。个股回测仍是单标的测试；最低佣金、整手、盘口、历史ST变化、IPO特殊涨跌幅和精确分红税未完整模拟。公司行为按对齐后的复权比例近似计权益。
- 组合回测按每日截面把模型排序分数融合后取前 N 名（默认20）等权持有，单股仓位上限默认5%（按调仓前权益计算，超出部分保留现金、不放大杠杆），可设置调仓间隔。撮合严格模拟 A 股 T+1（当日开盘买入最早次日开盘卖出）、开盘一字涨停不假设买入成交、开盘一字跌停不假设卖出成交、停牌不交易并按最近收盘价估值；卖出收 0.05% 印花税，买卖双边各收 0.03% 佣金与 0.1% 滑点，并逐笔记录未成交笔数。打分股票池与撮合股票池强制一致：流动性筛选裁剪股票池后，截面面板同步裁剪，避免排序选中没有行情、根本无法成交的股票。组合净值为本次实际采集股票池内按模型排序的结果，仍不是历史成分股组合，不能消除幸存者偏差。
- 配对筛选只使用训练期，当前稳定性只控制当前研究信号。收盘信号在下一日收盘模拟执行，随后才记持仓收益；对冲权重总名义敞口为1，计入再平衡、卖方印花税和可配置借券费。借券可得性及真实执行约束仍需单独验证。
- 扫描超过股票池快照有效期时重新获取完整股票池，并由后续股票复用新缓存；刷新失败会明确报错或停止生成有效信号。历史数据须与报价对应的已完成交易日匹配。

## PostgreSQL 与持仓

业务数据库为 `127.0.0.1:5432/quantify`，模式为 `public`。本地连接文件为 `config/database.local.json`，密码保存在该文件，不写入源码或日志；该文件已加入忽略列表。可用 `QUANT_PG_HOST`、`QUANT_PG_PORT`、`QUANT_PG_DBNAME`、`QUANT_PG_USER`、`QUANT_PG_PASSWORD` 环境变量覆盖。首次启动自动运行 `sql/001_portfolio_monitor.sql`，不会覆盖已有持仓。

| 表名 | 用途 |
| --- | --- |
| quant_watchlist | 六位代码唯一的自选、备注和监控开关 |
| quant_positions | 分批持仓、买入价格、股数、确认可卖数量、费用及编辑版本 |
| quant_position_audit | 持仓新增、编辑、删除前后快照 |
| quant_monitor_config | 后台开关、轮询参数、配对设置、心跳和错误 |
| quant_quote_snapshots | 行情快照、源时间、采集时间及原始字段 |
| quant_minute_bars | 股票代码与分钟时间唯一的不复权已完成分钟线 |
| quant_intraday_signals | 按股票、配对、策略和分钟去重的研究提醒 |
| quant_saved_backtests | 新回测参数、模型版本及逐日净值结果 |
| quant_schema_versions | 数据库结构版本 |

原日线下载缓存及接口诊断仍使用本地 SQLite，新业务状态、监控行情和回测结果保存到 PostgreSQL。已有旧回测未自动迁移。数据库异常时会报错，不会退回临时内存假装保存成功。

持仓支持同代码多批买入。成本为买入价乘股数加买入费用；浮盈亏不扣未来卖出费用。今日买入批次即使填有可卖数量，策略也按零可卖处理。历史批次按手工确认的可卖数计算，券商冻结和特殊交易规则需自行核对。编辑采用行锁和版本校验，避免多个页面覆盖修改；删除保留审计记录。

## 盘中任务

先在“自选与持仓”添加股票，再到“盘中监控”勾选开启并保存。设置保存在数据库，服务重启后恢复上次开关。后台任务在首次进入监控页时按需启动，也可以执行 `run_monitor.bat` 独立启动；Linux部署使用独立的 quant-monitor 服务，数据库咨询锁保证同一数据库只有一个采集任务。任务不会随浏览器关页停止，关闭全部程序进程后停止。

沪深快照使用新浪批量查询，失败或北交所股票使用东方财富备用。分钟线优先东财、沪深失败回退新浪。3至60秒为期望轮询间隔，网络耗时长时不会堆积并发请求；非连续竞价时段每60秒采集快照、每5分钟同步分钟线。公开源最多监控50只，超出明确停止并提示，不静默截断。周末、节假日、午休、源时间过期及分钟缺失均不会生成当前有效提醒。

单股规则使用当日最初30根分钟线估计噪声，卡尔曼先预测再更新，至少35根后评估残差、回升、量能和研究成本门槛；持仓参考ATR退出，遵守手工可卖数量和T+1。配对只用今日之前至少240根分钟线检验协整和对冲比例稳定性，再递推今日先验残差；未确认借券条件只显示观察。固定0.2%成本门槛仅为研究参数，不代替真实滑点、佣金和借券费用评估。

快照保留30天，分钟线90天，信号180天；任务每天清理一次过期监控数据，自选、持仓及修改记录保留。分钟规则尚未提供历史执行回测或盈利验证，页面上的信号为研究提醒，不会自动更改持仓或执行委托。

## 2.0机器学习管道

按《需求.txt》第四节「机器学习管道」的方案B实现，训练标签为 `股票未来N个基准交易日收益 - 沪深300同期收益`，不再训练绝对价格/绝对收益目标。`forward_return_N`仅用于Top/Bottom分组诊断，`target_N`才是模型监督标签；基准或任一股票端点缺失时不填充、不错移交易日。

选股先收集有效股票的历史，再建立共享截面模型；至少5只股票，同日特征或预测覆盖不低于本次有效股票池的80%。每个特征和预测均严格按日期标准化，均值0、总体标准差1；恒定特征变为0，完全相同的预测拒绝生成排序。百分位、Z分数均描述相对强弱，正超额不保证股票绝对上涨，低分表示相对弱势，不自动建立空头交易。

滚动验证按完整交易日切分，训练标签结束日必须严格早于测试起日。至少2个有效折、40个有效样本外日期；每日Rank IC平均值>0.02、使用N日滞后的HAC t>1.645、MAE优于训练中位数基线、Top超额>0且高于股票池均值、Top-Bottom>0才允许输出预测。指标阈值是固定研究门槛，不代表已证明未来有效；多模型、多周期筛选仍有多重检验风险。Top/Bottom为20%分组的N日重叠持有期平均收益，含绝对收益及超额收益，未扣交易费用，不能等同可执行组合净值。

模型、每日指标、池成员、来源、参考日期与上下文ID保存于 `models/market_context_v2.1.0.*`，历史截面保存在 `data/ml_panel_v2.1.0.parquet`。个股页与选股页读取相同上下文；日线日期或收盘价不匹配则拒绝复用，未包含的股票需重新扫描。旧版1.2逐股模型与2.0上下文已被当前版本取代并清理，不再占用磁盘，也不会被加载。历史回测每20日仅用当时已成熟标签重训及验证，并对当日完整股票池预测后取目标股票的信号；缺少截面时明确标记未产生模型交易信号。

2.1 起训练范式与存储分层同步升级。监督标签可以不再直接用超额收益回归，而是把每个交易日的截面超额收益按分位映射为 5 级相关度，用 LambdaMART（LightGBM）或 `rank:ndcg`（XGBoost）直接优化截面内排序，`group`/`qid` 为交易日，因此“看多”只在同日截面内部成立。排序模型的验证不检查 MAE（无量纲分数上的绝对误差没有意义），改用 NDCG@前20% 与固定随机种子基线之比，并要求 Rank IC 及其 HAC 显著性仍成立。每次重训只取最近 N 个交易日（默认 750≈3 年，0 表示不限）做滚动窗口，窗口内的标签结束日仍须早于测试起日。`auto` 模式会同时训练两种目标，按“先看是否通过验证、再看样本外 Rank IC”择优，并把两边的指标写进 `objective_selection` 以便复核。

中性化作为训练前的预处理接在因子生成之后：启用时对每个交易日截面用流通市值对数与申万一级行业哑变量做 OLS，残差即中性化后的因子，`neutral_*` 列在覆盖率达标时被面板采用；暴露数据来自 AkShare 行业成分与东财快照，缓存在 `data/panel/exposures/`。组合回测入口为 `services/portfolio_backtest.py::run_portfolio_strategy`，与扫描页共用同一次训练上下文。

当前截面为本次实际采集成功的股票池，不能声称历史全市场截面；使用当前股票成员回溯会有幸存者偏差。新增测试的确定性样本只在测试中使用，不进入行情或页面结果。完整测试：`QUANT_TEST_POSTGRES=1 .venv/bin/python -m unittest discover -s tests -v`；数据库测试使用随机独立模式并在结束时清理，未设置此变量时跳过数据库集成部分。
